# 知识库条目规范

> 目标：换一所学校 = 换一份 JSON + 一组 URL，前端代码零改动。

## 字段说明

| 字段 | 类型 | 必填 | 作用 |
|---|---|---|---|
| `school` | string | ✅ | 学校标识，多校配置时用于分区 |
| `id` | string | ✅ | 稳定唯一 ID，`类别.子类.动作` 命名，是模型引用条目的唯一凭据 |
| `category` | string | ✅ | 展示用分类，影响界面标签与检索加权 |
| `triggers` | string[] | ✅ | **口语化**触发词，覆盖学生的真实说法，是本地降级检索的主要依据 |
| `title` | string | ✅ | 事项名称，动词开头 |
| `summary` | string | ✅ | 一句话说明这是什么、为什么要办 |
| `entry.channel` | string | ✅ | 入口名称或部门，没有网址时也要能说清去哪 |
| `entry.url` | string | ⭕ | 仅填**已确认可访问**的官方链接 |
| `steps` | string[] | ✅ | 可照着做的步骤，3–6 条，每步一个动作 |
| `materials` | string[] | ✅ | 需要提前准备的东西 |
| `sla` | string | ⭕ | 时限、办结承诺、截止规则 |
| `source.title` | string | ✅ | 依据名称（手册条目、通知标题） |
| `source.url` | string | ⭕ | 可核验的原文链接 |
| `source.note` | string | ⭕ | 例如"链接待核验""以当学期通知为准" |
| `verified` | boolean | ✅ | 是否已与官方核对；`false` 会在界面显示「待核验」 |

## 写入原则

1. **不编造**。没有公开直达链接就留空 `entry.url`，在 `source.note` 里说明从哪儿进。
2. **不写需要登录才看得到的数据**（成绩、余额、宿舍分配）。
3. **`triggers` 写学生的话，不写公文术语**。写"没水""跳闸""卡丢了"。
4. **`steps` 是可执行动作**，不要写"了解相关规定"这种无法执行的话。
5. 政策类条目必须有 `sla` 或 `source.note` 提示时效性。

## 新增条目检查清单

- [ ] `id` 不重复，符合命名规则
- [ ] 至少 3 个 `triggers`，覆盖口语说法
- [ ] `entry.url` 已实际访问验证，或留空
- [ ] `source` 能指向具体依据，而不是"网上"
- [ ] 未核实的设为 `verified: false`
- [ ] 跑一遍 `npm run dev`，用该条目的口语说法检索能命中
