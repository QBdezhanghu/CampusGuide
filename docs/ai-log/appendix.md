## 一、使用原则

1. AI 用于方案讨论、代码生成、文案与文档整理；**取舍与验收由人完成**。
2. 所有 AI 产出的代码都经过人工阅读与修改，能够解释其作用。
3. 不使用 AI 生成虚构数据或网址；知识库中未核实的条目标注"待核验"。

## 三、关键 Prompt 与产出（精选）

### 示例：知识库 schema 设计

**Prompt**

> 我要做一个校园事务助手，用户说一句话，返回一张包含步骤、材料、入口、依据的行动卡。
> 请设计一个条目 schema，要求换一所学校时只替换数据、不改代码，并说明每个字段的作用。

**AI 产出**：字段清单（school / id / category / triggers / title / summary / entry / steps / materials / sla / source）

**人工修改**

- 增加 `verified`：未与官方核对的条目必须在界面上标注，对应赛事"资料来源与授权情况清楚"的要求
- `source` 允许多个字段留空：没有公开直达链接时如实说明，而不是让模型编一个
- 增加 `triggers`：作为断网时本地检索的唯一依据

**验证**：7 条真实说法测试，5 条命中、2 条正确兜底。

## 五、已知限制

- 知识库条目尚未与学校官方逐条核对，`verified=false` 的条目以"路径参考"为准。
- 大模型检索在未配置密钥时退化为关键词检索，长尾表达的召回率有限。
- 本工具不接入任何需要登录的系统，因此不提供真实进度查询。
